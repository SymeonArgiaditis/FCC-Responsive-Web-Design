Introduction

C++ is a general-purpose, compiled, statically-typed programming language. It's a large and powerful language, extending C with object-oriented, generic, and (later) functional programming features. Unlike a scripting language running inside a host environment, C++ is typically compiled directly to machine code and run standalone — though it can absolutely be embedded (game engines use it to expose objects to designers, for instance).

C++ contains a standard library of facilities — containers like std::vector and std::map, utilities like <chrono> and <algorithm> — plus a core language with strict typing, manual (or RAII-managed) memory control, and compile-time guarantees. Core C++ is extended constantly for specific domains:

  • Systems/embedded C++ adds low-level hardware access, minimal runtime overhead, and tight memory control — used in OS kernels, drivers, and microcontrollers.
  • Application C++ extends the core with frameworks (Qt, for GUI; Boost, for utilities) to build desktop apps, handle file I/O, networking, and more.

C++ and C

C++ is often described as "C with classes," and that's historically accurate but incomplete. C++ retains C's low-level control and manual memory management, but layers on a static, strong type system, classes, templates, and RAII (Resource Acquisition Is Initialization) — a pattern with no real equivalent in C, where an object's constructor acquires a resource and its destructor releases it automatically.

Where JavaScript is prototype-based with dynamic, forgiving typing, C++ is class-based with types resolved and checked at compile time. You do have to declare variable types (or let the compiler infer them with auto), and you do have to specify access — public, private, protected — on every class member. Nothing is loosely typed; a function's parameter and return types are fixed at compile time, and mismatches are compiler errors, not silent runtime coercions.

This is the opposite trade-off from JavaScript's free-form style: C++ asks for more upfront ceremony in exchange for catching entire categories of bugs before the program ever runs.

Hello world
              
cpp

              
  #include <iostream>
  #include <string>

  void greetMe(const std::string& yourName) {
      std::cout << "Hello " << yourName << std::endl;
  }

  int main() {
      greetMe("World");
      return 0;
  }

Save this as hello.cpp, then compile and run it:

              
Bash

              
  g++ hello.cpp -o hello
  ./hello

There's no Scratchpad-and-Ctrl+R here — C++ needs an explicit compile step before anything runs.

Variables

Variables are symbolic names for values, and identifiers follow similar surface rules to JavaScript: a C++ identifier must start with a letter or underscore (_); subsequent characters can be letters, digits (0-9), or underscores. C++ is case-sensitive, same as JavaScript.

The major difference: every variable must have a declared (or inferred) type, and that type is fixed for the variable's lifetime. 

              
cpp

              
  int temp99 = 42;
  std::string _name = "hello";
  auto number_hits = 100;  // compiler infers int

Some reserved-word and naming cautions carry over (don't shadow keywords, don't start with double underscores — those are reserved for the implementation), but the core shape of a legal identifier is basically the same as JS.
